# 本地 TTS 接入

本项目支持三种本地接入方式。第三方引擎、模型和运行环境需用户自行安装并遵守其许可证。

## Piper

适合已有 Piper 可执行文件和 ONNX 模型的场景。建议把模型放在独立目录，例如 `C:\tts-models\piper\voice.onnx`，先在终端验证 Piper 能生成 WAV，再在界面新增 Piper 模型。

## 本地 HTTP

适合 GPT-SoVITS、Fish Speech 等已经独立运行的服务。建议只监听环回地址，例如 `http://127.0.0.1:9880`。先用服务自身文档验证端点，再在工作台选择对应负载模式。

工作台不会自动安装或启动这些第三方服务，也不会猜测它们的鉴权和请求格式。

## 本地命令

命令模板支持：

- `{text}`：待合成文本
- `{output_path}`：工作台分配的输出文件
- `{model_path}`：模型配置中的路径
- `{ref_audio_path}`：声音配置中的参考音频
- `{ref_text}`：参考文本

示例：

```text
C:\tts-models\venv\Scripts\python.exe C:\tts-models\infer.py --text "{text}" --out "{output_path}" --model "{model_path}"
```

安全限制：

- 进程通过参数数组启动，`shell=False`。
- 输出必须位于工作台受控音频目录，参考文件必须位于受控参考目录。
- 执行时间限制在 1 到 120 秒。
- UI 元数据和公共错误不会回显完整命令、合成文本或受管绝对路径。
- 这仍然不是沙箱。模板中的程序拥有当前用户权限，只能运行可信代码。

## 排错顺序

1. 在工作台外验证第三方引擎。
2. 使用短文本和固定模型测试。
3. 确认输出格式与文件扩展名一致。
4. 检查端口、模型路径和外部虚拟环境。
5. 分享日志前删除密钥、文本、声音和本机路径。
